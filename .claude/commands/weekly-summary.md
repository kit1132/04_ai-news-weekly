# /weekly-summary

3リポ横断の AI ニュース週次サマリーを生成し、Draft PR として提出する。

## 実行コンテキスト
- 出力リポジトリ（書き込み）: `kit1132/04_ai-news-weekly`（本リポ）
- 入力リポジトリ（読み取りのみ）:
  - `kit1132/01_ai-news-master`
  - `kit1132/02_ai-news-copilot`
  - `kit1132/03_ai-news-industry`
- タイムゾーン: JST（Asia/Tokyo, UTC+9）
- 想定発火: 毎週日曜 09:00 JST（Routines）・手動トリガ可

## 不変条件
- 入力リポ（01〜03）の `digests/` 配下を**変更しない**（読み取りのみ）
- 既存週次ファイルを**上書きしない**

## ステップ

### 1. 日付・週番号の確定
1. 当日日付を JST で取得: `TZ=Asia/Tokyo date +%Y-%m-%d`
2. ISO 8601 週番号を取得: `TZ=Asia/Tokyo date +%G-W%V`（例: `2026-W18`）
3. 7日窓 = `[今日-6日, 今日]` の連続日付リストを生成

### 2. 既存ファイルチェック
- `weekly/{YYYY}/week-W{NN}.md` が `main` に既に存在する場合、生成中止して「既存ファイルあり: weekly/{YYYY}/week-W{NN}.md」と報告して終了

### 3. 入力ファイル収集
3リポ × 7日 = 最大 21 ファイルを GitHub MCP で取得:
- パス: `digests/{YYYY}/{MM}/ai-news-{YYYY-MM-DD}.md`
- 月をまたぐ場合（例: 4/27～5/3）はそれぞれ正しい `MM` ディレクトリを参照
- 取得失敗 / 404 のファイルは「欠損」として記録（リポ名・日付）

### 4. 全欠損チェック
- 21 ファイルすべて欠損の場合、生成中止して「7日全欠損のため生成中止」と報告して終了（空ファイルや空 PR は作らない）

### 5. ブランチ作成
- ブランチ名: `claude/weekly-summary-{YYYY}-W{NN}`
- ベース: `main`

### 6. 週次サマリー生成
以下の4セクション構成で `weekly/{YYYY}/week-W{NN}.md` を作成し、本ブランチにコミット。

#### 冒頭メタ情報
- 対象期間: `YYYY-MM-DD` 〜 `YYYY-MM-DD`
- ISO週: `YYYY-W{NN}`
- 入力ソース: 取得成功ファイル数 / 21
- 欠損がある場合のみ「欠損: [master] 2026-04-29, [copilot] 2026-04-30, ...」を列挙

#### セクション 1: 今週のハイライト
全ソース横断でインパクト順に 3〜5 件。各項目に <explanation_style> の 4 ステップを適用する。

#### セクション 2: カテゴリ別まとめ
日次ファイルの見出しで自動グルーピング。各項目末尾にリポタグを付与し、ソースURLを併記。
- 形式: `- [master] {見出し} — {ソースURL}`
- 重複は統合し、複数タグと URL を併記: `- [master][industry] {見出し} — {URL1}, {URL2}`
- リポタグは `[master]` / `[copilot]` / `[industry]` の3種類

#### セクション 3: 来週の注目予定
将来日付のイベントを統合。

#### セクション 4: 改善メモ集約
重複排除して統合。

### 7. Draft PR 作成
- タイトル: `weekly: AI news summary {YYYY}-W{NN}`
- ベース: `main`
- ヘッド: `claude/weekly-summary-{YYYY}-W{NN}`
- 本文: 対象期間・取得ファイル数・欠損リスト・自動生成である旨
- `draft: true`

<explanation_style>
## 適用範囲
この解説スタイルは、主に「今週のハイライト」セクションに適用する。
他セクション（カテゴリ別まとめ・来週の注目予定・改善メモ集約）は事実の整理を優先し、4ステップの厳密な適用は不要とする。
## 解説の構造
トピックの性質に応じて、以下のステップを適用してください。
1. 事実の提示：何が起きたのかを端的に述べる
2. 根拠の提示：定量データがあれば数字で、なければ技術的意義や業界への影響で裏付ける
3. 影響の具体化：このニュースが読者の日常・判断にどう波及するかを示す
4. 行動指針：「で、どうすればいいの？」に答える。明確な行動がない場合は「経過観察」と明示する
## 解説の原則
- 比較対象を置く：単体で評価せず、代替手段と並べて判断基準を渡す
- 判断の方向性を明確にする：「不要」なら切り捨て、「真似できない」なら代替行動へ誘導する。曖昧に濁さない
- 一貫したメッセージに収束させる：複数トピックを扱う場合、結論を一つの核心メッセージに集約し、異なる角度から補強する
- 情報量が増えても、読者がやるべきことはむしろ減るように構成する
- 感情や印象ではなく、根拠で議論する
- 「参考になります」「注目です」のような曖昧な締めは使わない
- 行動指針のない解説はしない
</explanation_style>

## 移行メモ（Cowork 原文からの差分）
原文 workflow のパス記述（`01_ai-news/daily/{年}/ai-news-daily-YYYY-MM-DD.md`）は実態と不一致のため、以下のように調整している：
- `01_ai-news/daily/{年}/` → `digests/{YYYY}/{MM}/`（3リポとも同一構造のためリポプレフィクス不要）
- `ai-news-daily-YYYY-MM-DD.md` → `ai-news-YYYY-MM-DD.md`（`daily-` 接頭辞は実ファイルに不在）
- `digests/ 配下は読み取り対象外` の一文は削除（現在の Source of Truth が digests/ のため）
- explanation_style / quality_check は原文ママ保全
