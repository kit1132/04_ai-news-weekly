# weekly-summary — AIニュース週次サマリー生成

## 目的

kit1132 の3つのソースリポジトリの直近1週間分ダイジェストを集約し、週次サマリー Markdown を生成して main に直接 push する。

## 前提

- タイムゾーンは JST（Asia/Tokyo）。当日日付は `TZ=Asia/Tokyo date +%Y-%m-%d`、ISO週番号 `<YYYY>-W<NN>` は `TZ=Asia/Tokyo date +%G-W%V` で取得する
- **対象週** = 実行日を含む ISO 週（月曜〜日曜）。通常は毎週日曜 9:00 JST に実行されるため、「対象週の月曜〜当日（日曜）」の完結した7日間になる
  - 日曜以外に手動実行された場合は進行中の週が対象になるため、冒頭注記に「部分週（〜実行日まで）」と明記する
- 作業ブランチは必ず `main`。feature ブランチ・PR は作らない
- 入力リポジトリへは一切書き込まない（読み取り専用）

## 入力（読み取り専用・3リポ横断）

| リポ | リポタグ | パス |
|---|---|---|
| `kit1132/01_ai-news-Master` | `[master]` | `digests/<YYYY>/<MM>/ai-news-YYYY-MM-DD.md` |
| `kit1132/02_ai-news-Copilot` | `[copilot]` | `digests/<YYYY>/<MM>/ai-news-YYYY-MM-DD.md` |
| `kit1132/03_ai-news-industry` | `[industry]` | `digests/<YYYY>/<MM>/ai-news-YYYY-MM-DD.md` |

取得方法（作業ディレクトリが 04_ai-news-weekly の場合）:

```
git clone --depth 1 https://github.com/kit1132/01_ai-news-Master.git /tmp/src-master
git clone --depth 1 https://github.com/kit1132/02_ai-news-Copilot.git /tmp/src-copilot
git clone --depth 1 https://github.com/kit1132/03_ai-news-industry.git /tmp/src-industry
```

対象週7日 × 3リポ = 最大21ファイル。月をまたぐ週は正しい `<MM>` ディレクトリを参照する。存在しないファイルは「欠損」として記録する（リポタグ・日付）。

## 手順

1. ブランチを main に揃える:
   ```
   git fetch origin main
   git checkout main
   git pull origin main
   ```
2. 出力先 `weekly/<YYYY>/week-W<NN>.md` が既に存在する場合は、何も変更せず「当該週は生成済み」と通知して終了する
3. 3リポの対象週分ダイジェストを読み取る
   - **21ファイル全欠損**: 生成を中止し、その旨を通知して終了
   - **一部欠損**: 取得できた分で生成し、冒頭に欠損リスト（リポタグ・日付の表）を明記
4. 下記フォーマットに従い週次サマリーを生成し、`weekly/<YYYY>/week-W<NN>.md` に保存する
5. `files.json` の配列先頭に新ファイルのパス（例: `weekly/2026/week-W24.md`）を追加する
6. コミット & プッシュ:
   ```
   git add weekly/ files.json
   git commit -m "Add AI news weekly summary for <YYYY>-W<NN>"
   git push origin main
   ```
7. push 後、`git log origin/main -1` で main に反映されたことを確認する

```
> 入力: 取得成功 N / 21（欠損があれば下の表に列挙）
> 生成日時: YYYY-MM-DD（JST）

（欠損がある場合のみ）
## ⚠️ 欠損ファイル通知
| 日付 | 欠損リポジトリ | 影響 |
|---|---|---|

## 今週のハイライト

3リポ横断でインパクト順に3〜5件。各件は `### N. タイトル — 一言の含意` の見出しに続けて
**要点** / **詳細** / **意味** の3段落で構成し、末尾に出典URLを箇条書きで付ける。

- **要点**: 何が起きて、なぜ重要か。**1〜2文・80字以内**。ここだけ読んで「読むか飛ばすか」を判断できるようにする
- **詳細**: 数値・スペック・日付・経緯。事実の裏付けを兼ねる。**1段落300字以内**（過去に880字の段落が生成されたため上限を設ける）
- **意味**: kit の仕事（AI/クラウド開発、コンサル提案）にどう関わるか

**書かないこと**:
- 一般論の助言（「〜を要件化すべき」「〜から着手するのが妥当」等）。読まれていないため2026-07-26に廃止した
- 材料がない段落を無理に埋めること。**該当する内容がなければその段落は省略する**（3段落を必ず埋めなくてよい）

## {カテゴリ名}

ハイライト以外のニュースをカテゴリごとに整理する。カテゴリ名は固定せず、当週の
3リポのダイジェストに出てきたカテゴリを自然に統合する（同名・類似は1つにまとめる）。
カテゴリ順は当週の件数または主要度順。

### {見出し} — [master]
- 詳細（重要項目には出典URL）

### {見出し} — [copilot][industry]
- 複数リポで重複する話題は1つに統合し、関与した全リポタグを付ける

## 来週の注目予定

3リポの「直近の注目予定」等から将来日付のイベントを統合し、日付順の箇条書きで。

## 改善メモ

3リポの「改善メモ」セクションを統合・重複排除して引き継ぐ。
リポ間の矛盾に気づいた場合もここに記録する。
```

### 統合の方針

- 同一ニュースが複数リポにある場合は情報量の多い方をベースに統合し、リポタグを併記する
- 矛盾する記述があれば両論併記し、改善メモに記録する
- URL は原文のまま記載する
- 日次の詳細をそのまま並べず、週単位での流れ・帰結（「週初の発表→週末の続報」など）が分かるように要約する

## 太字（`**...**`）の使い方

太字は「あとで検索・引用したくなる語」だけに使う。**文や節をまるごと太字にしない**。

- **1項目（`###` 単位）につき太字は3箇所まで**
- **1箇所は20字以内**の語句に限る。それを超える長さは太字にしない
- 対象は固有名詞＋バージョン（`Claude Code v2.1.220`）、金額（`$100M`）、日付、`%` などの数値
- 強調したい主張は太字ではなく**文の順序**（結論を先に書く）で示す
- 目安: 本文の太字比率は **10%以下**

2026-07-26 の実測（各ソース最新10ファイル・改善メモ除外）では、太字が
「多すぎる」と「1回が長すぎる」の2つの形で崩れていた。

| ソース | 太字率 | 1項目あたり | 1箇所の平均長 | 20字超の割合 |
|---|---|---|---|---|
| Copilot | 21.5% | 4.7箇所 | 26.1字 | 59% |
| daily | 18.7% | 4.6箇所 | 18.9字 | 40% |
| Master | 13.3% | 4.4箇所 | 15.6字 | 34% |
| weekly | 8.2% | 2.6箇所 | 14.3字 | 27% |
| industry | 6.5% | 0.5箇所 | 41.6字 | 82% |

太字が本文の2割を占めると、どこが重要かが判別できなくなる（太字が意味を失う）。
industry のように「回数は少ないが1回が41字」も同じ結果を招くため、回数と長さの
両方を守ること。

- main 以外のブランチへ push しない
- 既存の週次ファイルを上書きしない
